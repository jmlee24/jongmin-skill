# jongmin-dev-conductor — 다중 레인 개발 편성

정체성: **병렬 접합기**. 지휘부(메인 세션)는 구현 코드를 직접 쓰지 않고 **스코프 확정·레인
배선·직접 검증·리뷰 접합**만 한다. 핵심 성능은 **검증·명세·리뷰·쓰기를 최대한 겹치면서도
착지·판정을 T1 하나로 직렬화하는 능력**이다. 병렬성은 읽기 레인과 파일군이 분리된 쓰기
레인(worktree 격리)에서 얻고, 착지는 T1이 하나씩. 오류는 검증 층이 잡는다 — 병렬의 상한은
안전이 아니라 태스크 의존성(DAG)과 T1 소화 속도가 정한다.

쓰기 모드 3단계: ① `single-writer` (소규모·결합 강한 웨이브의 폴백) ② `pipeline` (쓰기 1개 +
검증·리뷰 병렬) ③ `parallel-write` (**기본** — DAG에서 파일군이 분리되는 태스크가 있으면.
분리 불가면 ②로, 소유권 위반·반복 충돌 시 ①로 폴백. 안전 전제는 아래 절).

## 발동 게이트

**적합** (하나 이상 해당):
- 커밋 3건 이상이 예상되는 다중 파일 구현 웨이브
- 무손실 최적화·동작 보존 리팩토링 등 **등가성(오라클) 검증이 결과의 핵심**인 작업
- 회귀 비용이 큰 고위험 변경 (데이터 정합성, 수치 동일성, 마이그레이션)
- 사용자가 편성/교차검증을 명시적으로 요청

**부적합** (일반 진행으로):
- 단일 파일·소규모 수정, 일상적 멀티파일 리팩토링
- 프로토타입·일회성 스크립트 등 리뷰 독립성의 가치가 낮은 작업

판단 기준은 **저장소 크기가 아니라 "웨이브 규모 × 회귀 리스크"**다.
소형 프로젝트라도 데이터를 깨뜨리면 안 되는 변환 로직이면 적합하고,
대형 프로젝트라도 한 줄 수정이면 부적합하다.

## Preflight (발동 직후, 레인 발진 전)

복사해서 체크하며 진행:

```
- [ ] git 저장소 확인, 기준 SHA 기록: BASE=$(git rev-parse HEAD)
- [ ] 워킹트리 상태 확인 — 더티면 기존 변경 파일 목록을 장부에 기록해 executor 변경과 구분.
      **병렬 쓰기 웨이브는 클린 트리에서만 시작** — 레인 worktree는 미커밋 변경을 못 본다
- [ ] 발진 배치 질문 1콜 (question-policy.md) — 미확정 항목만 모아 AskUserQuestion 1회:
      커밋 권한(항상 포함), 더티 트리 처리 방침(더티일 때), 범위 경계·성공 기준(모호할 때).
      이후 런 중 질문 금지 — 유예 3분류(defer/gate/block)로 장부 기록, 종료 배치로 제시
- [ ] codex 가용 확인: `codex login status` — 실패 시 읽기 레인을 Claude 반박 감사로 강등
- [ ] 프로젝트 규약 수집 — CLAUDE.md, 테스트 규약, 수치 표기 규약 등 에이전트 프롬프트에 복제할 목록 작성
- [ ] 게이트 명령 전수 수집 — 테스트·타입·린트 + **프로젝트 고유 검사기**(문서 검사기 등)까지,
      각각의 기준선 수치를 측정 SHA와 함께 기록 (실측: 고유 게이트 누락으로 레인 red + 매 프롬프트 수동 삽입)
```

런 중 즉시 질문 예외는 question-policy.md의 4종(불가역·금지선 충돌·사용자 변경 덮어쓰기
위험·3접근 소진)뿐이다.

## 편성

| 레인 | 바인딩 | 역할 | 제약 |
|---|---|---|---|
| 지휘 (T1) | 메인 세션 | 근거 수집, DAG 편성, 프롬프트 작성, 착지·판정, 리뷰 접합, 불일치 실측 판정, 최종 보고 | 구현 코드 직접 작성 금지 (검증 스크립트는 예외) |
| 쓰기 (T2) | Agent(`general-purpose`) + [executor-prompt.md](../../shared/executor-prompt.md) | 구현 + 테스트 + 레인 브랜치 커밋 | 파일군 분리 태스크만 worktree 병렬 — 같은 파일군 병렬 금지(불변), 발진 게이트: 미착지 완료 레인 0 |
| 읽기 (CX) | `codex exec` read-only — 실행 패턴은 [codex-lane.md](../../shared/codex-lane.md) | 다음 작업 명세 생성, 대안 제시, 반박 지향 교차검증 | 쓰기와 파일 충돌 없음 → 상시 병렬 가능. **소견은 자문** — 자동 반영 금지 |
| 리뷰 (T2) | `lane-reviewer` 에이전트 (없으면 `general-purpose`에 read-only 지시) | 착지된 커밋 범위 독립 리뷰 — 착지물 리뷰의 주도자 | 자기승인 금지 — 지휘부·쓰기 레인이 리뷰를 대신하지 않는다 |

티어 바인딩·승격 밸브·교차 리뷰 비대칭 규칙은 [model-tiers.md](../../shared/model-tiers.md)가
유일한 정의 지점이다. 모델 ID를 이 스킬이나 프롬프트에 박지 않는다.
리뷰(T2)와 읽기(CX)의 소견이 갈리면 지휘부(T1)가 실측으로 판정한다 — CX 지적은 반증 방법 없이 기각 금지.

## 웨이브 진행

**파이프라이닝 원칙**: 벽시계의 주적은 T1의 동기 대기와 쓰기 직렬성이다. 병렬의 상한은 레인
수가 아니라 **태스크 의존성(DAG)**이 정한다 — DAG가 허용하는 폭만큼 쓰기를 병렬화하되, 착지는
T1이 하나씩 직렬로. 인증 유지 시 벽시계 하한 ≈ DAG 임계 경로 + Σ(T1 판정) + full 게이트
(등가성 등 자동 승격 웨이브는 착지 단위 full로 하한이 커진다 — landing-check.md).
직렬로 돌면 벽시계 ≈ 레인 시간의 합이 된다 (실측: 5시간 웨이브의 원인).

복사해서 체크하며 진행:

```
- [ ] 1. 근거 수집 + DAG 편성 (지휘부 직접) — 의존성 그래프·파일군 소유권 맵·전 레인 프롬프트 선행 작성
- [ ] 2. 쓰기 레인 발진 — DAG 독립 태스크는 worktree 병렬 발진, 백그라운드, 동기 대기 금지
- [ ] 3. 병행: 읽기 레인 발진 + 후속 프롬프트 보강 (T1 유휴 금지)
- [ ] 4. 착지·검증 (T1 직렬, 생략 금지) — 범위 확인 → 착지 → 검증 실행 백그라운드 ∥ diff 검토 → 판정
       → 끝나면 즉시 대기 중 레인 발진/다음 착지
- [ ] 5. 리뷰 패스 (착지 후 SHA 범위, 백그라운드) — 커밋 N 리뷰 ∥ 태스크 N+1 쓰기
- [ ] 6. 리뷰 접합 — 결과 도착 시점에, 살아있는 쓰기 레인 우선
- [ ] 7. 최종 보고 — 전 리뷰 도착·접합 확인 + 시간 장부
```

**1. 근거 수집 + DAG 편성** — 대상 코드/문서를 직접 읽고, 가능하면 재현 실험으로 가설을 먼저
확증한다. 이 근거의 질이 executor 프롬프트의 질을 결정한다. DAG 간선·소유권·계약 변경의 전제가
되는 인용은 [evidence-liveness.md](../../shared/evidence-liveness.md)로 `LIVE` 판정된 것만 쓴다
(아래 소유권 맵 실존 확인은 그 기계 층의 일부). 웨이브 계획은 선형 커밋 목록이
아니라 **태스크 DAG + 파일 소유권 맵**으로 산출한다 (읽기 레인에 위임 가능): 어떤 태스크 쌍이
파일군 분리로 동시 발진 가능한지, 어떤 체인이 의존인지, 공유 계약 변경(시그니처·스키마·공용
타입)은 어느 루트 태스크로 선행 착지하는지 확정하고, **전 레인의 executor 프롬프트를 발진 전에
미리 작성**해 의존 커밋이 착지되는 즉시 다음 레인을 발진할 수 있게 한다.
소유권 맵은 **기존 파일과 생성 예정 파일을 구분**한다 — 기존 파일은 `ls`로 실존 확인 후
배정하고 (실측: 배정 파일 2개가 실존하지 않아 executor가 발견·보고 — 없는 파일을 Owned로
주면 executor가 임의 위치에 만든다), 생성 예정 파일은 신규 파일 허용 목록(executor-prompt.md
6요소)에 올린다 — 부모가 기존 디렉터리면 실존 확인, 부모도 신규(새 패키지·마이그레이션
디렉터리 등)면 디렉터리째 허용 목록에 명시한다.

**2. 쓰기 레인 발진** — [executor-prompt.md](../../shared/executor-prompt.md)의 5요소를 모두 채워 발진한다
(채워진 실물 예시가 그 문서에 있다). T2가 프롬프트 개선 후 재시도로도 실패하면 승격 밸브 적용
([model-tiers.md](../../shared/model-tiers.md)).
핵심은 **사양 이탈 보고 요구**다: executor가 사양의 결함을 실측으로 거부하는 것이
최선의 산출물일 수 있다.

DAG에서 파일군이 분리된 독립 태스크는 worktree 격리로 병렬 발진한다:

```bash
git worktree add "<scratchpad>/lane-<task>" -b "lane/<task>" <발진 베이스>
```

- **발진 베이스**: 모든 부모 태스크가 착지된 메인 라인 시점 (부모 없는 태스크는 BASE).
  다중 부모(A→C←B)는 부모 전부 착지 전 발진 금지 — 일부만 착지된 베이스에서 발진하지 않는다
- **발진 게이트**: 미착지 완료 레인이 있으면 새 발진 금지 — T1 착지 소화 속도에 자동 수렴한다
  (완료는 비동기라 큐가 일시적으로 2가 될 수 있다 — 발진 중지로 해소). 큐 대기는 시간 장부에 기록
- **실측 배타 구간**: 지휘부가 실측(GPU·실기·처리량 측정)을 돌리는 동안, 측정 자원과 경합하는
  **실행 레인** 발진 금지 — 측정 시작 전 **경합 실행 레인 0** 확인, 경합 여부가 애매하면
  경합으로 간주한다(보수 기본값 — 실측 사례도 CPU pytest가 GPU 처리량 측정을 오염, 경합은
  비자명하다). 측정 구간을 시간 장부에 배타 구간으로 기록. T1의 비실행 작업(프롬프트 작성·
  diff 검토·원격 자문 회수)과 명백한 비경합 레인은 계속한다 — 파이프라이닝 원칙 유지
- 같은 파일군을 만지는 레인 병렬 금지 (불변). 프롬프트에 worktree 경로·레인 브랜치·
  6요소(소유권·계약 — executor-prompt.md)를 명시한다
> 함정: 에이전트는 세션 컨텍스트·프로젝트 메모리를 못 본다 — 필요한 규약은 전부 프롬프트에 복제하라.

**3. 읽기 레인 병렬 발진** — CX는 **상시 2슬롯 병렬**이 기본이다 (스레드 분리):
- CX-A: 다음 태스크 명세 생성 (명세가 딛는 근거의 생존성 반박 포함 — evidence-liveness.md)
- CX-B: 방금 착지물 adversarial 반박
- 고위험·등가성 작업이면 CX-C(아키텍처·인터페이스 충돌 전용) 추가 — 상한은 접합 큐 규칙
  ([codex-lane.md](../../shared/codex-lane.md) 발진 상한)이 결정한다. 산출 형식은 codex-lane.md
  표준을 따른다 (반박형은 Top 5, 명세형·규명형은 임무별 지정).

CX의 강점 배치는 생성·반박이다 — 착지물의 최종 리뷰는 리뷰 레인(T2)이 주도한다.
**선행 스킬 산출물 인정**: 같은 작업에 대해 warplan(계획 반박)·deep-audit(감사)이 이미 CX 산출물을
만들었다면 재발진 없이 읽기 레인 입력으로 쓴다 — 단, 자동 채택 금지는 동일하고, 산출 시점의
기준 SHA와 현재 트리의 차이를 확인해 후속 executor 프롬프트에 합류 지점을 명시한다.
> 함정: 명세 시점 ≠ 착지 시점. 읽기 레인이 본 트리와 착지 후 트리가 다르면,
> 후속 executor 프롬프트에 그 차이(선행 커밋과의 합류 지점)를 명시하라.

**4. 착지·검증** — 완료 보고를 그대로 믿지 않는다. **착지·검증 단위는 레인(커밋 범위)**이다:
착지는 T1이 레인 하나씩 직렬로, 검증은 **실행/판정 분리**로 진행한다
(강도 동일, T1의 실행 대기만 제거 — [landing-check.md](../../shared/landing-check.md)):

1. **범위 확인**: `git diff --stat <발진 베이스>..<레인 TIP>`으로 소유권 맵 준수 확인
   (인자 없는 diff는 커밋된 레인에서 빈 결과를 낸다) — Forbidden 파일·범위 밖 변경은 즉시 중단·보고
   (예외: 임무-소유권 모순 보고가 첨부된 최소 침범은 T1 직접 판정 — landing-check.md)
2. **착지**: 메인 라인 HEAD가 직전 착지 TIP인지 확인(외부 커밋 감지 → 중단·보고) 후,
   레인 커밋을 순서대로 cherry-pick — 또는 레인 rebase 후 **fast-forward로 메인 라인을 실제로
   전진**시킨다 (rebase만으로는 메인이 움직이지 않는다). **SHA가 바뀌므로 이후 검증·리뷰는
   전부 착지 후 범위 `<직전 TIP>..<새 TIP>` 기준**이며, 레인 SHA → 착지 후 범위 매핑을 장부에 기록.
   충돌 시: 진행 중 연산을 즉시 abort(`git cherry-pick --abort` / `git rebase --abort`)해 클린
   상태를 복원하고, T1이 직접 해소하지 않는다(코드 작성 금지) — 갱신된 합류 지점을 명시해 레인 재발진
3. **검증 실행 발진**: impact-scope 테스트·결정론 게이트를 **통합 트리에서 백그라운드 동시 발진**
   (worktree 안 green은 착지 검증이 아니다 — 파일군이 분리돼도 공유 타입·import로 결합될 수 있다).
   병렬 웨이브면 contract drift 확인 포함 (공개 API diff·스키마·생성물·lockfile·픽스처 변경 여부)
4. **병행 검토**: 실행이 도는 동안 T1은 핵심 diff를 직접 검토
5. **판정**: 도착한 출력 원문을 T1이 직접 읽고 판정 → 레인 worktree 제거 +
   `git branch -D lane/<task>` (cherry-pick 착지는 조상 관계가 없어 `-d`가 거부된다)

발견 사항은 다음 프롬프트에 반영한다.
> 함정: 서브에이전트 완료 통지는 완료가 아니다. 지휘부 직접 판정 전까지 완료 선언 금지.
> 실행을 백그라운드에 위임해도 판정 위임은 금지 — 출력 원문을 T1이 읽는다.

**5. 리뷰 패스** — 커밋 게이트 판정 직후 읽기 레인을 **병렬 발진**한다 (전부 착지 후 SHA 범위
고정, 백그라운드 — 리뷰어 입력에 테스트 결과가 필요하므로 판정 전 발진 금지):
- **quick 리뷰**: 차단 이슈(critical)만 신속 탐지 — 다음 쓰기 진행 여부는 이것만 보고 판정
- **deep 리뷰**: `lane-reviewer` 전면 리뷰, 집중 축 지정(논증의 구멍, 전제 성립, 오라클 강도)
- quick·deep 모두 [reviewer-prompt.md](../../shared/reviewer-prompt.md) `change` 모드 템플릿을 채워
  발진한다 (SHA 범위·축·테스트 원문 — executor 자기 보고 전달 금지)
- **CX adversarial**: 고위험·등가성·오라클 작업에서 반박 레인 추가

상한: 읽기 레인 총 3개 기본(예외 4개), 커밋별 deep 리뷰 동시 2개까지 — 그 이상은 중복 지적과
접합 순서 꼬임으로 이득이 준다. **판정 큐는 T1 하나**: 중복 지적은 T1이 병합. 접합 시점은
심각도로 고정한다 — **critical 즉시 중단·접합 / major는 같은 파일을 만지는 다음 쓰기 발진 전
접합 필수 / minor·nit는 종료 게이트 묶음**. 접합 전 freshness rule(codex-lane.md)로 리뷰
기준 SHA와 현재 HEAD의 overlap을 확인 — stale 리뷰는 자동 접합 금지.
> 함정: 리뷰어에게 HEAD나 워킹트리가 아니라 SHA 범위를 줘라. executor 자기 보고 공유 금지.
> 함정: 접합이 진짜 병목이다 (wave2 실측: 꼬리 9분). 리뷰 도착 즉시 접합 프롬프트를 준비해두라.

**6. 리뷰 접합** — 지적사항은 쓰기 레인이 살아 있으면 그 레인에 접합한다(같은 파일을 만지는
시점이 접합 비용이 가장 싸다). 레인이 끝났으면 새 쓰기 레인으로 처리한다.

**7. 최종 보고** — 커밋 목록, 전후 지표, 리뷰 항목별 처리 결과, 다음 결정 지점,
**시간 장부**(레인별 시작/종료/대기 — [ledger.md](../../shared/ledger.md) 3절. 다음 웨이브의
병목 튜닝은 추정이 아니라 이 실측으로 한다). 유예 결정이 있으면 종료 배치 1세트로 제시
(question-policy.md).

- 레인 실패: 서로 다른 접근 3회까지 시도 후 사용자에게 보고하고 중단
- 작업 범위 밖 파일 변경 감지 시 즉시 중단·보고
- 읽기 레인 무응답: 데드라인(기본 15분) 초과 시 잡 정지, 결과 없이 진행할지 판단
- 웨이브 중단 시 정리: 백그라운드 잡 정지, 생성한 worktree 제거, 현재 상태 보고
- **컴팩션 임박·세션 경계**(계정 전환, 기기 이동): `handoff` 스킬로 스냅샷을 뜬 뒤 중단한다 —
  재개는 handoff restore가 담당

## 성공 기준

- 전 커밋 착지 + 지휘부 재실행 테스트 green + 클린 트리 (결정론 게이트 포함 — landing-check.md)
- 리뷰 critical 0 (major는 접합 처리 완료)
- **회귀 가드 (조건부)**: 이 웨이브가 deep-audit CONFIRMED major/critical 구조 결함을 고치는
  웨이브면, 재발 방지 가드(테스트·타입 제약·린트 규칙 중 가장 싼 층)를 **같은 웨이브에서 착지**한다.
  가드는 "수정 전 실패 → 수정 후 통과"를 증명해야 하며(불가능하면 사유 보고), 문자열 매칭보다
  구조적 검사를 우선하고, 가드 자체도 리뷰 대상에 포함한다. 새 도구 설치 금지.
- 문서 정합까지 같은 웨이브 내 완료
- push 없음 (사용자 명시 지시 전까지)

## parallel-write 안전 전제

"인터페이스가 명확하면 쓰기 병렬이 안전하다"는 직관은 조건부로만 맞다 — 실제 실패 원인은
인터페이스가 아니라 **숨은 결합**(전역 상태·import 사이클·shared fixture/mock·config/env·
마이그레이션 순서·생성 파일·lockfile·snapshot·포맷터 대량 diff)이다. 병렬 발진의 표준 전제:

```
- [ ] 계약 동결 선행 — 공유 시그니처·스키마·공용 타입 변경은 DAG 루트 태스크로 먼저 착지, SHA 기록
- [ ] 파일 소유권 disjoint 맵 — 레인별 Owned/Forbidden 목록 (공용 타입·픽스처·config·lockfile은
      전 레인 Forbidden — 변경이 필요하면 별도 직렬 태스크로 DAG에 편성)
- [ ] 레인별 worktree 격리 + executor 프롬프트 6요소(소유권·계약 — executor-prompt.md) 필수
- [ ] 착지 게이트에 contract drift 확인 포함 (웨이브 진행 4절)
```

폴백: 소유권 위반·계약 변경 감지 즉시 해당 병렬 배치 중단 → 산출 diff는 patch 후보로만 보존 →
pipeline/single-writer로 재계획. 오류는 검증 층이 잡지만, 이 전제들은 잡힌 뒤의 **재작업
비용**을 줄이는 장치다 — 검증이 있다고 생략하지 않는다.

## 환경 노트

- OMC 비의존이 기본 전제다. `lane-reviewer`가 없는 환경이면 `general-purpose`에 read-only 지시로 대체.
- 세션의 에이전트 수 가이드라인은 **동시 실행 기준**으로 해석한다 — 웨이브 누적 총합이 아니다
  (실측: 누적 16개 웨이브도 동시 실행은 최대 4). 누적 제한으로 읽으면 웨이브 후반 리뷰가 굶는다.
- 착지 프로토콜의 git 역학(범위 diff·충돌 abort·rebase/ff·branch -D)은 스모크 테스트로 실측
  검증됨(Windows Git Bash, 2026-08-12 — 전부 이식성 있는 git 기본기라 Linux 동일). 다만 **실전
  병렬 웨이브는 미검증** — 첫 웨이브에서 시간 장부로 큐 대기·착지 충돌 빈도를 실측하고 반영할 것.
- **머지 트레인(투기적 착지)은 보류**: 커밋 N 검증 완료 전에 N+1을 겹쳐 착지하는 패턴. red 시
  N+1의 검증 실행 1회분만 버려지고 코드는 재착지되므로 리스크는 작지만, 실행/판정 분리가 이미
  실행 대기에서 T1을 빼내므로 한계 이득이 작다. 장부에서 "착지 검증 실행 대기"가 여전히
  병목으로 실측되면 투기 깊이 1로 도입 검토.

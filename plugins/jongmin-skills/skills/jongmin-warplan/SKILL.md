# jongmin-warplan — 편성표형 계획

정체성: **결정 압축기** — 계획 = 실행 프롬프트의 묶음 + **사용자 판단이 필요한 결정의 최소 집합**.
계획만 산출하고 실행하지 않는다 — 실행은 단계별 라우팅 대상에 위임한다. 단계 나열이 아니라,
각 단계가 즉시 발진 가능한 수준까지 내려간 편성표와 압축된 결정표가 산출물이다.

경계 명확화: "실행하지 않는다"는 **계획된 작업을 실행하지 않는다**는 뜻이다. 계획 수립의 입력을
만드는 read-only 레인(T2 사전 조사, CX 반박 자문)은 이 스킬의 정당한 활동이다 — 워킹트리를
변경하는 순간 경계 위반이다.

티어: 계획 작성 T1, 사전 조사 T2 병렬, 계획 반박 CX 자문 — [model-tiers.md](../../shared/model-tiers.md).

## 절차

```
- [ ] 1. CX 위험 스카우트 선발진 (백그라운드) + 모호성 인터뷰 배치 (기본 0~2문항)
- [ ] 2. 근거 수집 + 생존성 검증 — 대상 코드·문서 직접 확인 (큰 범위면 T2 병렬 조사), 인용마다 LIVE 판정
- [ ] 3. 편성표 작성 — CX 1차 결과는 결정 지점·위험 항목으로만 흡수 (자동 반영 금지)
- [ ] 4. CX 2차 반박 (resume) → T1 접합
- [ ] 5. 채팅으로 제시 — 유예 결정은 종료 배치 1세트로, 사용자 확정
```

**1. 모호성 인터뷰** — [question-policy.md](../../shared/question-policy.md) 발진 배치:
**기본 0~2문항, 최대 4, AskUserQuestion 1콜**. 실행 결과를 바꾸는 질문만
(범위 경계, 성공 기준, 되돌림 허용도, 우선순위 충돌 시 원칙). 취향 질문 금지.
안 물은 항목은 **보수적 가정을 명시해 계획의 `가정/유예 결정` 절로 기록**한다 (가정 없는 생략 금지).
작성 중 발견한 추가 질문거리도 즉시 묻지 않고 결정 지점으로 흡수한다.
**무인 모드**(사용자 부재 명시, sortie 등 질문 금지 컨텍스트): 인터뷰 0문항 — 전부 가정으로.

**2. 근거 수집** — 계획의 각 주장에는 코드·실측 근거가 붙어야 한다. 추측으로 단계를 만들지 않는다.
근거는 실존만으로 부족하다 — [evidence-liveness.md](../../shared/evidence-liveness.md) 절차로
기준 SHA를 기록하고 인용마다 `LIVE/STALE/DEAD/UNVERIFIED`를 판정한다. **`LIVE`만 확정 전제**,
나머지는 가정·위험·유예로 내린다 (죽은 코드·stale 문서를 인용한 계획은 틀린 전제 위의 계획이다).

**3. 편성표 작성** — 단계마다 4항목 필수:

```
### 단계 N: <제목>
- 실행 주체: 직접 | T2 executor | conductor 웨이브 | sortie | loop
- 크기: 신선한 컨텍스트 1개가 소화 가능한가 (아니면 분할)
- 검증 오라클: <이 단계의 완료를 판정하는 실행 가능한 검증>
- 결정 지점: <사용자 판단 필요 항목 — sortie 실행 시 유예 장부 항목으로 변환됨>
```

각 단계는 [executor-prompt.md](../../shared/executor-prompt.md) 5요소(병렬 웨이브 단계는
6요소 — 소유권·계약 포함)로 즉시 컴파일 가능해야 한다.
측정 단계는 추가로 `답할 질문 / 답하지 못할 예상 후속 질문`을 적고, 1벌 dry-run으로 원자료·조인 키
보존을 확인한다 (실측: 3.2시간 캠페인이 조인 키 부재로 다음 질문에 답 못 함 — 착지 시점 방어보다 설계 시점이 싸다).
컴파일이 안 되는 단계는 아직 계획이 아니다 — 더 쪼개거나 근거를 보강한다.

라우팅 기준: 고위험 다커밋 → conductor / 부재 중 시간 박스 → sortie / 완료 조건 반복 → loop /
소규모 단일 파일 → 직접.

**CX 이중 투입** — 실행 대기는 백그라운드로 병렬화되지만 접합 비용은 0이 아니다
(codex-lane.md 발진 상한) — 그 한도 안에서 반박 깊이를 2배로:
- **1차 스카우트** (절차 1, 근거 수집과 병렬): 요구사항 자체의 위험·누락·모호점을 반박시킨다.
  결과는 편성표 작성의 결정 지점·위험 입력으로만 흡수 — 자동 반영 금지.
- **2차 반박** (절차 4, 1차 스레드 resume): 완성된 편성표에 대해 "이 계획이 실패할 가장
  그럴듯한 이유 5개 + 질문 누락 + 레인 분할 오류 + **핵심 전제의 인용 재확인**(죽은 코드·stale
  문서·주석을 실행 근거로 오인한 곳 — evidence-liveness.md 필수 축)"을 요구.
- 양쪽 모두 [codex-lane.md](../../shared/codex-lane.md) 산출 형식 표준(Top 5 + severity + 검증법).
  소견은 자문이며 T1이 반증 방법과 함께 접합·기각을 판정한다.

**5. 제시** — 계획은 채팅으로. 파일 산출은 사용자가 명시 요청할 때만 (전역 문서 규약).
유예 결정은 [question-policy.md](../../shared/question-policy.md) 종료 배치 형식으로 —
"지금 답해야 하는 것"과 "나중에 바꿔도 되는 것"을 분리해 1세트로 제시한다.

# jongmin-loop — 완료 조건 반복 실행

ralph 계열 자율 루프의 자기 스킬 버전. 정체성: **one-task-per-loop + 이중 종료 게이트 + 서킷 브레이커**.
시간 박스가 아니라 완료 조건으로 달린다 (시간 박스는 jongmin-sortie).

티어 배치는 [model-tiers.md](../../shared/model-tiers.md): 실행 T2, 종료 판정 T2(독립 컨텍스트), 최종 착지 검증 T1.

## Preflight

```
- [ ] 완료 조건을 오라클로 확정 — 실행 가능한 검증 명령/테스트로 표현. 불가능하면 루프 부적합, 중단
- [ ] 진행 장부 생성 — 형식은 ledger.md, 위치는 전역 루프 규약의 progress.txt (repo 내 예외)
- [ ] 태스크 분해 — 루프 1회 = 태스크 1개 크기로 장부에 기록
- [ ] 기준 SHA 기록, 실행 메타(CX 모델 등) 기록
```

## 루프 절차

```
- [ ] 1. 장부에서 태스크 1개 꺼내기 (one-task-per-loop — 욕심내지 않는다)
- [ ] 2. T2 쓰기 레인 발진 — executor-prompt.md 5요소
- [ ] 3. 착지 검증 — landing-check.md, 지휘부 직접
- [ ] 4. 장부 갱신 (완료/실패 + 에러 지문)
- [ ] 5. 장부에 남은 태스크가 있으면 1로, 없으면 종료 게이트로
```

## 이중 종료 게이트 — 둘 다 통과해야 완료 선언

1. **장부 게이트**: 진행 장부의 전 항목 완료 + 오라클(완료 조건 검증 명령) green
2. **독립 판정 게이트**: `lane-reviewer`(T2)에 SHA 범위·diff·테스트 결과**만** 전달해 판정받는다.
   실행 프롬프트·실행자의 자기 보고는 공유하지 않는다 (동계열 편향 완화).
   critical 지적이 있으면 장부에 태스크로 추가하고 루프 재진입.

허위 완료 방지가 목적이다: 실행자의 "완료했다"는 게이트 입력이 아니다.

## 서킷 브레이커

- **파일 변경 없는 루프 3회 연속** → 중단·보고 (공회전 감지)
- **동일 에러 3회** → 접근 전환 (전역 규약의 "서로 다른 접근 3회"와 정합).
  동일 에러 동치 기준: 실패 테스트명 일치, 또는 exit code + stderr 핵심 라인(경로·주소 정규화 후) 일치
- 3회 접근 전환 후에도 실패 → 사용자에게 보고하고 중단
- 작업 범위 밖 파일 변경 감지 → 즉시 중단·보고

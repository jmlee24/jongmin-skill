# handoff — 세션·계정 인수인계

정체성: **세션 경계에서의 무손실 상태 이전**. 얇은 절차형 스킬 — T1 직접 수행, 위임 없음.
conductor·loop·sortie의 "컴팩션·중단 후 재개" 갭을 이 스킬이 담당한다.

## save — 스냅샷 생성

**진입 게이트 — 발동 조건 재확인**: 산출물의 주 소비자가 누구인가?
**지금의 사용자가 소비할 것이면 응답 본문**이다 — save를 하지 말고 응답으로 낸다.
파일은 주 소비자가 **미래 세션·기계**일 때(컴팩션 임박·계정 전환·중단),
또는 사용자가 파일을 명시 요청했을 때만 만든다 (실측: "새 세션용 프롬프트로 달라"는
요청에 150줄 파일 + 3줄 포인터로 응답한 사례 — 구체 스킬 조항이 전역 규약을 이겼다).
**기기 이동은 예외**: 이 파일도 장부도 새 기기로 따라가지 않는다 — 사용자가 나를 수 있는
**자기완결 응답 본문**(새 세션 첫 프롬프트)으로 낸다.

두 모드가 있다:
- **`save` (기본, 이탈 저장)** — 스냅샷 후 활성 백그라운드 잡 정지, 생성한 worktree 제거.
- **`save --keep-lanes` (중간 저장)** — 레인을 살려둔 채 체크포인트만 뜬다. 스냅샷에 레인 ID·시작
  시각·데드라인·산출물 위치와 함께 **"레인을 정지하지 않았음" 경고를 반드시 기록**한다.
  (실전 검증에서 기본 save가 진행 중인 CX 감사를 죽일 뻔한 사례에서 분리 — Codex 논의 합의안.)

위치: `~/.claude/jongmin-ledgers/<프로젝트명>/<YYYY-MM-DD>-handoff.md` ([ledger.md](../../shared/ledger.md) 경로 규칙).

> 턴 주의: deep-audit 등 `disallowed-tools`를 쓰는 스킬과 같은 턴이면 Write가 차단될 수 있다 (실측).
> 이 경우 handoff는 별도 턴에서 실행하라.

```
- [ ] 기준 상태: 브랜치, HEAD SHA, 워킹트리 상태(더티 파일 목록), 미커밋 diff 요약
- [ ] 진행 장부 경로 + 미완료·유예 핵심의 **자기완결 요약** — "스냅샷 시점 사본, 정본은
      장부, 불일치 시 장부 우선"을 명시 ([ledger.md](../../shared/ledger.md) 정본 단일화 —
      참조만 남기면 장부 유실·부재 시 무손실 이전 계약이 깨진다)
- [ ] 활성 레인: 백그라운드 잡·에이전트·codex 스레드 ID와 각각의 상태
- [ ] 다음 단계: 재개 시 제일 먼저 할 일 1~3개 (명령 수준으로 구체적으로)
- [ ] 유예된 결정: 장부 유예 절의 사본 (정본 표기 동일 — 불일치 시 장부 우선)
- [ ] 계정 회계: 이 작업이 소모한 계정(개인|법인), 재개 권장 계정
- [ ] 민감정보 미포함 확인 (토큰·키 금지)
- [ ] 기록한 SHA·경로·장부·명령의 실존만 T1이 기계 확인 (evidence-liveness.md 기계 층 —
      CX는 발진하지 않는다: 컴팩션 임박에 분 단위 지연은 스냅샷 자체를 실패시킨다).
      검증 못 한 구조적 주장은 UNVERIFIED로 표기해 보존 — 꾸며서 확정하지 않는다
```

스냅샷 후 (기본 save만): 활성 백그라운드 잡 정지(기록한 PID·잡 핸들로만 — 패턴 일괄 종료 금지),
생성한 worktree 제거, 중단 상태를 사용자에게 보고.
`--keep-lanes`면 레인 상태 요약만 보고하고 아무것도 정지하지 않는다.

## restore — 스냅샷 복원

```
- [ ] 최신 handoff 파일 읽기 — 여러 개면 우선순위 기본값으로 자동 선택: 같은 cwd → 최신
      mtime → 미완료 항목 있는 것 → 현재 HEAD와 가장 가까운 SHA. 전부 동률일 때만 질문
      (question-policy.md). 선택한 파일과 이유를 보고에 명시
- [ ] 기준 SHA와 현재 HEAD 비교 — 다르면 그 사이 변경을 요약해 보고 (모른 척 진행 금지)
- [ ] 워킹트리 상태 대조 — 스냅샷의 더티 목록과 현재가 다르면 차이 보고
- [ ] 진행 장부 로드, "다음 단계" 항목부터 재개 제안 — 다음 단계를 결정하는 주장은
      [evidence-liveness.md](../../shared/evidence-liveness.md)로 T1 기계 검증. 다음 중 하나면
      CX 반박을 **백그라운드 발진**하고 결과 접합 전엔 그 주장에 의존한 쓰기만 gate:
      스냅샷 이후 HEAD 변경이 관련 파일과 겹침 / 다음 단계가 구조·호출 경로·문서 해석에
      의존 / 근거가 STALE·UNVERIFIED (실측: 스냅샷의 "다음 단계"가 2회 틀렸던 사례)
- [ ] 유예된 결정이 있으면 재개 전에 사용자에게 제시 (이때는 물어봐도 되는 시점이다)
```

## 이력

폐기 결정만 남긴다 (릴리스 서사는 git 이력, v1 2026-08-08 ~ 현재):
- `--dry` 모드 기각 — save 진입 게이트가 흡수: 전달 가능하면 save 자체를 하지 않는다 (v1.3)
- 무조건 레인 정지 폐기 — 기본 save(이탈)와 --keep-lanes(중간 체크포인트)로 분리 (v1.1)

# 쓰기 레인 프롬프트 템플릿

`general-purpose` 에이전트 + T2([model-tiers.md](model-tiers.md))로 발진한다. 아래 5요소를 **모두** 채운다 —
빈 요소가 있으면 발진하지 않는다.

```
[임무] <구현 대상 한 줄 + 왜 하는지 한 줄>

1) 필독 문서
   <루트/폴더 CLAUDE.md, 테스트 규약, 관련 설계 문서의 경로 목록.
    "읽어라"가 아니라 경로를 나열한다.>

2) 커밋 단위
   <분할 계획: 커밋 1 = ..., 커밋 2 = ...>
   메시지 형식: <프로젝트 형식 그대로>. push 금지.

3) 검증 요구
   <프로젝트가 요구하는 가장 강한 오라클을 명시.>
   - 등가성 작업이면 비트/바이트 동일성 수준(직렬화 결과 비교 등)을 요구한다.
     근사 비교(allclose류)를 등가성 주장에 쓰는 것 금지.
   - 기준선/카운터가 있으면 재잠금 방향을 명시한다.

4) 규약 복제
   <프로젝트 메모리·수치 표기 규약 등, 에이전트가 볼 수 없는 규칙의 전문을 여기 붙인다.
    에이전트는 이 프롬프트 밖의 컨텍스트를 못 본다.>
   🔴 아래 2항은 프로젝트와 무관하게 항상 복제한다 — 없으면 발진하지 않는다:
   - 문서 변경 — 신규 .md allowlist: <경로 | 없음>, 미기재 생성 금지. 갱신할 정본: <경로 |
     해당 없음>, 같은 내용을 다른 문서에 복제 금지. 임무가 문서를 명시하지 않으면
     계획·요약·보고는 응답으로 낸다.
   - 사양 이탈은 멈추고 실측 근거와 함께 보고한다 (5) 보고 형식 참조)

5) 보고 형식
   - 커밋 해시 목록
   - 테스트 결과 원문 (요약 금지)
   - 사양 이탈 판단은 근거와 함께 전부 보고.
     사양이 틀렸다고 판단되면 구현을 멈추고 실측 근거로 보고하라 —
     그것이 최선의 산출물이다. 사양뿐 아니라 지휘부가 전달한 근거·리뷰
     소견도 실측으로 반박할 수 있다 — 전달된 근거가 죽은 코드·stale 문서이거나
     기준 SHA와 어긋나면(evidence-liveness.md) 같은 조항으로 멈추고 보고한다.
```

## 채워진 실물 예시 (축약)

```
[임무] parse_rows()의 행 단위 dict 생성을 컬럼 벡터 방식으로 교체 — 프로파일 실측 61%가 이 함수, 출력 등가성 보존.
1) 필독: CLAUDE.md / tests/README.md / docs/data-format.md
2) 커밋: ①등가성 하니스(기존 출력 pickle 고정) ②벡터화(하니스 green 유지). `refactor: 한국어 설명`, push 금지.
3) 검증: 샘플 3종 직렬화 바이트 비교 — allclose 금지. pytest 전체 green, 신규 실패 0.
4) 규약 복제: 수치 표기 소수점 6자리 고정(docs/data-format.md 3절 전문) / 새 문서 파일 생성 금지
5) 보고: 커밋 해시 + pytest 원문. 하니스 차이 발견 시 중단, 바이트 diff와 함께 보고.
```

## 병렬 쓰기 확장 — parallel-write 레인 필수 (= 6요소: 5요소 + 소유권·계약)

병렬 쓰기 레인(conductor parallel-write 모드)에서는 5요소에 더해 6번째 요소를 필수로 채운다:

```
6) 소유권·계약
   - Owned files: <이 레인만 수정 가능한 파일 목록>
   - 신규 파일 허용: <경로·패턴과 이유 | 없음> — 미기재 파일 생성은 금지.
     착지 시 지휘부가 --diff-filter=A로 대조한다 (landing-check.md).
     임무가 요구하는 미기재 신규 파일이 생기면 임무-소유권 모순과 동일하게 처분한다
   - Forbidden files: <읽기만 허용, 수정 금지 — 공용 타입·픽스처·config·lockfile 포함>
   - Exclusive resources: <테스트 DB·포트·캐시·생성물 경로·포맷터/생성기 영향 범위 | 없음>
     — 파일이 disjoint여도 이 자원이 겹치면 병렬 금지. rename·delete도 그 파일 소유권에 속한다
   - Frozen contracts: <동결 커밋 SHA + 동결된 시그니처·스키마 목록>
   - Integration assumptions: <다른 레인 산출물에 대한 가정>
```

소유권 밖 파일 수정이나 동결 계약 변경이 필요해지면 **수정 전에 멈추고** 「경로 · 필요 이유 ·
최소 변경 범위」를 침범 제안으로 보고한다 — 그것이 최선의 산출물이다. T1이 Frozen·공용
Forbidden·타 레인 Owned·배타 자원 충돌을 확인해 소유권 맵을 갱신하고 같은 레인을 재개하며,
공용·타 레인 소유와 겹치면 재승인 없이 직렬 태스크로 전환한다. 승인 기록 없는 Owned 밖 변경은
착지에서 차단된다 (landing-check). 병렬 불변식은 executor 자율 판단으로 깨지 않는다
(실측: 침범 필요성 판단이 옳았던 사례 1 · 중단→재승인→재개가 싸고 안전했던 사례 2 —
판단 가치는 보고로 살리고 실행 권한은 T1에 둔다).

Owned 파일이라도 **최상위(공개) 심볼 삭제·시그니처 변경은 커밋 전에 보고**한다 — 다른 레인이
그 심볼을 소비 중일 수 있다 (실측: 각자 worktree green, 통합 트리 12 errors). 착지에서 타 레인
소비처 grep으로 대조된다 (landing-check).

프롬프트에는 **worktree 경로·레인 브랜치**도 함께 명시한다 — 커밋은 레인 브랜치에만,
착지는 지휘부가 한다.
worktree 레인 프롬프트에는 다음 표준 문구를 포함한다 (실측: 레인 5개가 같은 환경 결손
실패를 보고, 매 프롬프트 수동 삽입했던 사례):

> worktree는 추적 파일만 복제한다. gitignore된 데이터(픽스처·실측 자산)는 없으므로
> 그것을 읽는 테스트는 환경 결손으로 실패한다 — 신규 실패와 구분해 보고할 것.
> 필요하면 메인 트리를 읽기 전용으로 참조한다.

## 주의

- 같은 파일군을 만지는 쓰기 레인을 병렬로 띄우지 않는다.
- 선행 커밋이 있는 웨이브 중반 발진이면, CX 레인 명세가 본 트리와 현재 트리의
  차이(합류 지점)를 프롬프트에 명시한다.

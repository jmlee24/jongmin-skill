# 문서 위생 — 생성·배치·초과·참조·정본·소각의 유일한 정본

정책은 이 파일 한 곳에만 둔다 — 스킬·템플릿은 집행 문장(sentinel)만 갖고 여기를 재서술하지
않는다. (실측: "새 문서 금지" 한 줄은 집행 지점 없이 반복 위반 — 문구 미복제 저장소 신규 .md
30일 59건 vs 복제 웨이브 0건. 참조 22곳이 물린 런북 절은 삭제 자체가 차단됐다.)

## 생성 게이트
새 문서 파일은 사용자 명시 요청 또는 발진 프롬프트의 신규 .md allowlist에 있을 때만.
계획·요약·진행 보고는 응답 본문으로. **3목적지 분류** — 산출물은 주 소비자로 목적지를 정한다:
지금의 사용자가 소비 → 응답 본문 / 현재 실행만 소비 → scratchpad(세션과 함께 소멸) /
미래 세션·기계가 소비하거나 재계산 비용이 큼 → 장부 경로(ledger.md). repo 정본은 넷째 목적지가
아니라 "프로젝트의 현재를 담는 문서"에만 해당한다.

## 배치 게이트 (기존 문서에 절·내용을 추가할 때)
① 주 소비자 판정(3목적지) ② 대상 문서의 주제 범위 일치 ③ 1회성(특정 사건·날짜 대응) 콘텐츠는
정본 문서 삽입 금지 — 응답·외부 전달물로. **분량은 배치 근거가 될 수 없다.**

## 용량 초과 처리 (예산 게이트에 걸렸을 때 — 순서 고정)
막기만 하는 예산은 우회를 낳는다. ① 그 문서 안의 stale·중복을 먼저 소각 ② 그래도 초과면
주제 단위 분할(이때의 새 문서는 정당한 생성 — allowlist로 보고) ③ 무관 문서로의 이관은 어떤
경우에도 금지 ④ 예산 자체가 부적절하면 채우거나 우회하지 말고 예산 조정을 보고.

## 정본 규칙
하나의 주장·결정·상태에는 canonical path 하나 — 다른 문서는 참조만, 복제하지 않는다.
예외: 경계 스냅샷(handoff)은 자기완결 사본 + "불일치 시 정본 우선" 표기로 사본이 정본을 이기지
않게 한다. 정본을 변경하면 알려진 소비처(참조하는 문서·코드)를 함께 확인한다.

## 참조 규칙 (참조는 의존성이다 — 삭제 비용을 만든다)
- 편의 참조 금지: "이 링크가 없으면 독자가 길을 잃는가"에 No면 걸지 않는다. 비교·해설 언급은
  링크 없이 텍스트로.
- 방향 제한: 이력·폐기·일회성 문서 → 현행 정본 링크 금지(필요하면 시점 SHA로 고정 인용).
  코드·설정 파일 → 문서 절 앵커 참조 금지.
- 절 앵커(#heading)보다 문서 단위 참조 — 절 개편이 참조를 깨지 않게.
- 실측: 정본 절 하나에 참조 22곳(설정 yaml 주석 포함)이 물려 절 삭제가 차단된 사례.

## 소각 (웨이브·작업 종료 게이트)
이 작업이 생성·갱신한 문서 전건을 **keep / merge / delete / follow-up**으로 판정한다:
① 코드·테스트·git 이력으로 대체되는가 ② 다음 세션이 읽어야 하는가. 유지(keep)는 사유 1줄.
git 추적 문서의 delete는 git 삭제로 충분하다(이력으로 복구 가능) — 루프 규약(.old/)이 적용되는
컨텍스트는 그 규약을 따른다. 소각 시 그 문서를 참조하던 곳(참조 인벤토리)을 함께 제거한다.

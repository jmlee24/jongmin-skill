# 착지 검증 체크리스트

서브에이전트·레인의 완료 통지는 완료가 아니다. 지휘부(T1)가 직접 검증하기 전까지 완료 선언 금지.

복사해서 체크하며 진행:

```
- [ ] git log로 보고된 커밋이 실제 존재하는지 확인
- [ ] git status로 클린 트리 확인 (범위 밖 변경 감지 시 즉시 중단·보고)
- [ ] 테스트 스위트 직접 재실행 — 보고된 결과를 믿지 않는다
- [ ] 결정론 게이트 실행 (아래 규칙)
- [ ] 핵심 diff 직접 검토 (git diff <BASE>..<TIP>)
- [ ] 발견 사항을 다음 프롬프트/장부에 반영
```

## 결정론 게이트

LLM 교차검증은 상관된 맹점을 공유한다 (두 모델이 모두 틀릴 때 60%가 같은 오답 — ICML 2025).
테스트 외에 프로젝트의 결정론 도구를 오라클 층으로 실행한다:

- **프로젝트에 이미 설정된 도구만** (타입체크·린트 등) — 게이트를 위해 새 도구를 도입하지 않는다
- 빠른 것 우선: touched-scope 명령이 있으면 그것을, 전체 스캔이 분 단위면 리뷰 게이트로 내리고
  최종 보고에 "미실행 리스크"로 기재
- 실패는 일괄 차단이 아니라 **4분류 후 판정**: 신규 회귀(차단) / 기존 실패(장부 기록, 진행) /
  범위 밖 실패(기록) / 비결정 실패(재실행 확인) — 레거시 경고가 쌓인 프로젝트에서 게이트가
  소음이 되는 것을 막는다

- 등가성 작업이면 비트/바이트 동일성 수준 오라클로 재확인 — 근사 비교(allclose류)를 등가성 주장에 쓰는 것 금지
- 독립 리뷰(lane-reviewer)에게는 **SHA 범위·diff·테스트 결과만** 준다 — 실행 프롬프트와 실행자의
  자기 보고를 공유하지 않는다 (동계열 편향 완화)
- "문제 없음" 결론도 어떤 검증을 수행했는지 근거와 함께 — 검증 없는 승인은 산출물이 아니다

# 착지 검증 체크리스트

**운영 불변식**: 서브에이전트·레인의 완료 통지는 완료가 아니다. T1이 직접 검증하기 전까지 완료 선언 금지.

검증은 2단 게이트다 — 강도를 낮추는 게 아니라 full 검증의 실행 시점을 옮기는 구조.
(근거: 커밋마다 전체 스위트+full 차등을 돌리던 관행이 벽시계 시간의 주요 원인 — 실측 5시간 웨이브)

검증은 **실행/판정 분리**로 진행한다: 실행(테스트·게이트)은 백그라운드에 위임 가능하지만
판정 위임은 금지 — 출력 원문을 T1이 직접 읽는다. 강도는 동일하고 T1의 실행 대기만 제거하는 구조다.

## 커밋 게이트 (착지 단위마다 — impact-scope)

게이트 단위는 **착지 단위(레인의 커밋 범위 `<직전 TIP>..<새 TIP>`)**다 — 레인에 커밋이 여러 개면
범위 전체를 한 게이트로 검증한다.

```
- [ ] (병렬 웨이브) 착지 전 git diff --stat <발진 베이스>..<레인 TIP>으로 배정 파일군 준수 확인
      (인자 없는 diff는 커밋된 레인에서 빈 결과) — 범위 밖 변경 감지 → 즉시 중단·보고.
      예외: T1 승인 기록이 있는 침범 제안(executor-prompt.md 재승인 프로토콜)은 갱신된
      소유권 맵 기준으로 판정한다 — 승인 기록 없는 Owned 밖 변경은 차단.
      추가 파일은 `git diff --name-status --diff-filter=A`로 신규 파일 허용 목록과 대조
- [ ] 추가된 `.md`를 **모드 무관하게**(단일 쓰기 포함) 발진 프롬프트의 신규 .md allowlist와
      대조 (`git diff --name-status --diff-filter=A -- '*.md'`) — 미기재 생성은 차단.
      정책 정본은 doc-hygiene.md
- [ ] 보고된 SHA는 **전건 `git cat-file -e "<sha>^{commit}"`으로 커밋 실존 확인**
      (실측: 허구 SHA 4건 완료 보고 사례 — `-t`는 객체 존재만 증명하므로 커밋 타입까지 강제),
      git status 클린. 같은 레인이 서로 다른 내용으로 2회 보고하면 어느 쪽도 신뢰하지 않고
      `git log <발진 베이스>..<레인 TIP>`으로 저장소에서 직접 판정한다
- [ ] 게이트 시작 전 검증 대상 HEAD·tracked diff를 기록하고, 출력·exit code 회수까지 착지·소스
      편집을 금지한다 (실측: 게이트 실행 중 T1 편집으로 가짜 실패). 값이 달라지면 결과 폐기·재실행
- [ ] 검증 실행 발진 (통합 트리에서, 백그라운드 동시 — 게이트마다 출력 파일·exit code를 분리
      캡처하고 대상 SHA 범위를 함께 기록한다. 출력이 섞이면 원문 판정이 불가능하다):
      · impact-scope 테스트 — 변경 함수·모듈의 직접 테스트 + 변경된 public API의 1-hop 호출자 테스트
        + 변경 파일이 속한 패키지의 touched-scope 테스트 + 영향받는 fixture·schema·config 테스트
      · touched-scope 결정론 게이트 — 프로젝트에 이미 설정된 타입체크·린트만, 새 도구 도입 금지
      · (병렬 웨이브) contract drift — 공개 API·스키마·생성물·lockfile·픽스처 변경 +
        삭제·시그니처 변경된 최상위 심볼의 타 레인 소비처 grep (실측: 각자 green, 통합 12 errors)
      worktree 안 green은 착지 검증이 아니다 — 반드시 착지된 통합 트리에서 실행한다
- [ ] 실행이 도는 동안: 핵심 diff 직접 검토 (git diff <BASE>..<TIP>, 착지 후 SHA 기준)
- [ ] 판정: 도착한 출력 원문을 T1이 직접 읽는다.
      실패는 4분류(신규 회귀=차단 / 기존 실패=기록 / 범위 밖=기록 / 비결정=재실행)
- [ ] 장부 표기: "부분 착지 / full pending" — full 게이트 전까지 완전 검증으로 선언하지 않는다
```

## 웨이브 full 게이트 (웨이브 종료·큰 단위마다)

```
- [ ] 전체 테스트 스위트 재실행
- [ ] full 차등·뮤테이션 (등가성 웨이브 — 근사 비교 금지, 바이트 동일성만.
      대상·시간 상한은 편성 시 확정해 장부에 기록한다 — 상한 없는 게이트는 측정 불가)
- [ ] 전체 결정론 게이트
- [ ] 문서 소각 판정 — 웨이브가 생성·갱신한 문서 전건 keep/merge/delete/follow-up (doc-hygiene.md)
- [ ] 전 리뷰 접합 상태 확인 후에만 웨이브 완료 선언
```

## 자동 full 승격 — 아래 조건이면 커밋 단위에서도 full 게이트

오라클·테스트 하니스 변경 / 등가성이 결과의 핵심 / deep-audit major·critical 수정 /
마이그레이션·데이터 정합성 변경 / 보안·권한·동시성 변경

## 공통

- 독립 리뷰어에게는 **SHA 범위·diff·테스트 결과만** 준다 — 실행 프롬프트와 실행자의
  자기 보고를 공유하지 않는다 (동계열 편향 완화)
- "문제 없음" 결론도 어떤 검증을 수행했는지 근거와 함께 — 검증 없는 승인은 산출물이 아니다
- 검증 명령의 종료 코드는 파이프 없이 출력 파일과 별도 캡처가 기본이다 (`cmd > out.txt; echo $?`).
  파이프가 불가피하면 종료 코드는 `${PIPESTATUS[0]}`(Bash 한정)으로 잡는다 — 파이프 뒤의
  `$?`는 마지막 명령(tail 등)의 것이다 (실측: "PYTEST_EXIT=0"이 무의미해 재실행)
- 기준선 수치는 측정 시점 SHA와 함께 적는다 (`2922 passed @ <SHA>, 직전 세션 실측`) —
  다음 세션·웨이브는 착수 전 재측정한다. 단, SHA·환경 지문이 동일함을 확인했고 재측정
  비용이 크면 라벨된 기준선을 재사용할 수 있다 (라벨 없는 수치는 재사용 불가)

## 검증 함정 (실측)

- **집계 일치는 항목 대응을 증명하지 않는다** — 조인 키로 항목을 맞춰 확인하고, 같은 키에
  행이 여러 개일 수 있는지 먼저 확인한다 (실측: 집계 717=717이었으나 라벨 조인은 861, 같은 함정 2회)
- **측정 캠페인 전 드라이런 1벌** — 산출물을 열어 답하려는 질문에 필요한 키가 실제로 들어
  있는지 확인한 뒤 본 측정을 돌린다 (실측: 8벌 실행 후에야 조인 키 부재 발견)
- **항등식 자기검증은 뮤턴트로 반응성을 확인한다** — 어떤 항을 흔들어도 잔차가 0이면 그
  항등식은 그 항을 검증하지 못하는 것이다 (실측: processed 7→99에도 잔차 0)
- **측정 판독 독립 게이트** — 측정 캠페인의 수량·인과 판독을 정본·handoff에 넣기 전, 독립
  T2(read-only)에 질문·모집단 정의·전체 원산출물·집계 코드·판독문을 맹검 입력하고 **기존 집계
  코드의 재실행이 아닌 전체 모집단 독립 계산 + 비중첩 반대 슬라이스 재검산**을 요구한다.
  하나라도 유지되지 않으면 UNSUPPORTED (실측: 저자 자기검증만 거친 판독 2건이 게이트 전부
  green인 채 정본에 등재, handoff로 다음 세션까지 전파 — 사용자 후속 질문으로만 발견)
